# ТЗ на тестирование — Buyer MVP (Stage 1)

Черновик для ревью на соответствие `TEST_COVERAGE.md`. Покрывает три экрана:
Главная, Каталог, Карточка товара (`buyer_mvp/`), контракт — Catalog API
(`/catalog/groups`, `/catalog/products`, `/catalog/products/{id}`).

---

## 1. Пользовательские сценарии

| # | Сценарий | Экран |
|---|---|---|
| 1 | Открыть главную, увидеть дерево категорий | Главная |
| 2 | Поиск с главной → переход в каталог с фильтром `search` | Главная → Каталог |
| 3 | Клик по категории → переход в каталог с фильтром `group_id` | Главная → Каталог |
| 4 | Просмотр каталога, список товаров | Каталог |
| 5 | Поиск в каталоге | Каталог |
| 6 | Сортировка по названию / по цене | Каталог |
| 7 | Сброс фильтра категории | Каталог |
| 8 | Пагинация (вперёд/назад) | Каталог |
| 9 | Открытие карточки товара по клику | Каталог → Карточка |
| 10 | Просмотр всех предложений продавцов | Карточка |
| 11 | Просмотр ленты фото оффера (0/1/N) | Карточка |
| 12 | Возврат назад с карточки | Карточка |

## 3. REST API — соответствие полей контракту

### `GET /catalog/groups`
| Поле | Статус | Тест |
|---|---|---|
| id | используется (ключ React, навигация) | косвенно |
| parent_id | используется (построение дерева) | нужен тест на дерево 2 уровней |
| name | отображается | ✔ |
| sort_order | используется (сортировка списка) | нужен тест порядка |
| product_count | отображается | ✔ |

### `GET /catalog/products`
| Поле | Статус | Тест |
|---|---|---|
| id | используется (навигация) | ✔ |
| name | отображается | ✔ |
| min_price | отображается (парсинг string→number) | нужен тест форматирования |
| offer_count | отображается (склонение слова) | нужен тест на 1/2/5 |
| photos | отображается (0 или 1 URL) | нужен тест на пустой массив → плейсхолдер |
| page/limit/total | используется (пагинация) | нужен тест границ (последняя страница) |

### `GET /catalog/products/{id}`
| Поле | Статус | Тест |
|---|---|---|
| id, name | отображается | ✔ |
| description | отображается, nullable | **нужен тест null** |
| offers[].seller_name | отображается | ✔ |
| offers[].price, unit | отображается | ✔ |
| offers[].stock | отображается | ✔ |
| offers[].description | отображается, nullable | **нужен тест null** |
| offers[].photos | отображается **лентой, весь массив** | **было покрыто только `photos[0]` — исправлено, требуется regression-тест на 0/1/3+ фото (см. п.6)** |

### Ошибки
| Код | Тест |
|---|---|
| 404 (товар не найден/не виден) | нужен отдельный сценарий на карточке — текст «Товар не найден» |
| Сетевая ошибка / недоступен сервер | нужен сценарий ErrorState + кнопка «Повторить» |

## 6. Регресс-кейс: `offer.photos[]`

Отдельно фиксируем как обязательный regression-тест (был найден Валентином, дефект тестового покрытия по методологии, п.9 `TEST_COVERAGE.md`):

> Дано: `GET /catalog/products/{id}` возвращает оффер с `photos.length === 3`.
> Ожидается: на экране отображаются все 3 превью в ленте, количество миниатюр === `photos.length`, клик по миниатюре меняет главное фото.
> Регресс: раньше отображался только `photos[0]`, лишние фото игнорировались.
